# Вклад в Jot

Изменения этого форка обсуждаются через [Issues](https://github.com/outsid3rx/open-jot-transcribe-macOS/issues) и [Pull requests](https://github.com/outsid3rx/open-jot-transcribe-macOS/pulls). В PR опишите проблему, поведение после изменения, выполненные проверки и известные ограничения.

## Правила

- Не добавляйте API-ключи, токены, записи пользовательской речи и сертификаты в код, тесты или CI. Для контрактных тестов используйте подставной HTTP-транспорт и синтетические данные.
- Сохраняйте исходные уведомления об авторских правах и условия [лицензии Apache 2.0](LICENSE). Код сторонних проектов не переносится без проверки его происхождения и лицензии.
- Используйте существующие [DesignTokens](App/Sources/DesignSystem/DesignTokens.swift) и [MotionTokens](App/Sources/DesignSystem/MotionTokens.swift). Пользовательские строки добавляются в оба ресурса локализации — ru и en.
- Аудио записывается до его передачи в API. Изменения сети, восстановления и вставки должны сохранять исходный текст и исправимые ошибки в истории. Очистка не должна терять пригодную расшифровку.
- Не добавляйте телеметрию, загрузку истории или отправку данных другому API без явного выбора пользователя.
- Изменения инструкций очистки проверяйте на самокоррекциях, вопросах, командах, списках, именах и числах. Контрактные тесты проверяют протокол, но не качество облачной модели; результаты таких проверок указываются в PR с точным уровнем доказанности.

## Локальная работа

Основная сборка требует полного Xcode и XcodeGen:

```bash
./scripts/build.sh
./scripts/test.sh
```

Для Command Line Tools:

```bash
./scripts/build-clt.sh
./scripts/verify-api-contract.sh
```

Используйте изолированные настройки, временную историю и тестовые ключи. Не запускайте платные проверки моделей в обычном наборе тестов. Изменения пользовательских сценариев дополнительно проверяются в собранном приложении.

[Архитектура](docs/ARCHITECTURE.md), [документация API](docs/design/external-transcription-providers-plan.md), [конфиденциальность](docs/PRIVACY.md) и [выпуск](docs/RELEASING.md) должны соответствовать поведению кода. Исторические материалы в `docs/design` служат контекстом, а не действующими требованиями.
