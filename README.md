# Jot

Голосовой ввод для macOS с настраиваемыми API и моделями.

Автор форка — [Max Zernyaev](https://github.com/outsid3rx) · Apache 2.0
</div>

Проект — форк [оригинального Jot](https://github.com/google-gemini/jot-gemini-transcribe-macOS) от Ammaar Reshi. Эта версия добавляет сторонние API, отдельную очистку текста и выбор языка интерфейса. Исходный код форка: [outsid3rx/open-jot-transcribe-macOS](https://github.com/outsid3rx/open-jot-transcribe-macOS). Оригинальные уведомления об авторских правах и лицензия сохранены. Это не официальный продукт Google.

Удерживайте клавишу диктовки, произнесите текст и отпустите её — расшифровка появится в текущем приложении. Аудио сохраняется локально до его отправки в API. В истории можно посмотреть исходный и обработанный текст, прослушать запись и повторить распознавание.

| Жест | Действие |
| --- | --- |
| Удерживать `fn` | Запись; отпускание запускает распознавание и вставку |
| `fn` + `Пробел` | Запись без удержания; нажатие `fn` завершает её |
| `Esc` | Отмена; длинные записи остаются в истории |

Клавиша меняется в общих настройках. Двойное нажатие для фиксации записи можно включить отдельно.

## Установка и первый запуск

Нужна macOS 14+. Скачайте архив для архитектуры своего Mac из [Releases](https://github.com/outsid3rx/open-jot-transcribe-macOS/releases), распакуйте и перенесите `Jot.app` в Applications. Архив `arm64` предназначен для Apple Silicon; наличие сборки для Intel определяется файлами конкретного релиза.

**Первый запуск:** сборка без Developer ID и нотариализации Apple может быть заблокирована macOS как приложение неизвестного разработчика. После попытки запуска откройте **«Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть»** и подтвердите открытие Jot. [Инструкция Apple](https://support.apple.com/ru-ru/102445).

1. Разрешите доступ к микрофону и универсальный доступ во время первоначальной настройки.
2. В разделе **«API и модели»** укажите провайдера, базовый URL, точный идентификатор модели и сохраните ключ.
3. Выберите язык транскрибации: «Авто» или поддерживаемый моделью код, например `ru`.
4. Удерживайте клавишу диктовки и произнесите текст.

## Провайдеры и модели

Предустановленные варианты подключения — Google Gemini и Polza. Для другого провайдера выберите **«Совместимый API»**. URL и обе модели всегда можно вводить вручную; встроенного каталога и ограничения фиксированным списком моделей нет.

| Тип API | Что отправляется | Относительный путь |
| --- | --- | --- |
| Транскрибация файла | WAV в multipart; модель и необязательный язык | `audio/transcriptions` |
| Чат с аудио | JSON с `input_audio: {data, format: "wav"}` и инструкцией транскрибации | `chat/completions` |
| Gemini Interactions | FLAC и параметры нативного распознавания | `v1beta/interactions` |
| Gemini Generate Content | FLAC в запросе старого Gemini API | `v1beta/models/<model>:generateContent` |

Базовый URL включает префикс и версию API, но не конечный маршрут. Например, при базе `https://api.example.com/v1` файловый запрос пойдёт на `/v1/audio/transcriptions`. Укажите модель так, как она обозначена у провайдера, включая префикс, если он требуется.

HTTPS обязателен; HTTP разрешён для localhost. Не помещайте ключ в URL. Ключи сохраняются в Keychain отдельно для провайдера и адреса API. Доступ к конкретной модели проверяется фактическим запросом.

Совместимость с API зависит от провайдера. Сверьте маршрут, формат аудио и поддерживаемые поля с его документацией. Аудиочат может ответить на сказанное вместо расшифровки; файловое распознавание не требует текстовой инструкции модели.

## Очистка текста и языки

**«Очищать и оформлять текст» выключено по умолчанию.** При включении выбранная текстовая модель получает отдельный запрос: убрать слова-паразиты, применить самокоррекции, исправить очевидные ошибки и оформить явные списки. Можно использовать API распознавания или отдельные URL, ключ и модель очистки.

Исходная расшифровка сохраняется до очистки. При ошибке, превышении лимита ожидания или отклонении результата проверкой сходства возвращается исходный текст с локальными словарными заменами.

В разделе «Очистка текста» можно задать время ожидания от 1 до 120 секунд, по умолчанию 10. Лимит охватывает весь запрос очистки, включая ожидание и повтор при ограничении частоты запросов; время транскрибации в него не входит. При обновлении существующие настройки и записи истории без этого параметра получают значение 10 секунд. Прекращение ожидания не гарантирует отмену обработки или списания у провайдера.

Три отклонённых результата за сутки выключают текущую очистку с уведомлением. Проверка сходства не гарантирует сохранение смысла. Цена и скорость зависят от выбранного API; очистка добавляет платный текстовый запрос.

Для совместимого API доступны автоопределение языка и явный код. В режиме «Авто» поле `language` не отправляется. Gemini использует автоматическое определение. Поддержку явного языка проверяйте по контракту модели.

В **«Общие» → «Язык интерфейса»** доступны **Русский** (по умолчанию) и **English**. Выбор применяется после перезапуска. Он не меняет язык диктовки и не переводит расшифровки; системные диалоги используют язык macOS.

Нативный Smart-режим и Live доступны только для соответствующего Gemini API. Live требует стандартного адреса и модели, автоматического языка и выключенной дополнительной очистки. Совместимые API получают файл после окончания записи.

## История и приватность

Обычный повтор сохраняет провайдера, URL, модель и язык исходной записи. Ошибка ключа или баланса одного API не останавливает очередь другого. **«С текущей моделью»** отправляет сохранённое аудио в выбранный сейчас API и создаёт новую запись, сохраняя старый результат. Отложенные запросы могут выполняться при запуске, восстановлении сети и изменении ключа.

У приложения нет собственного сервера и телеметрии. Данные обрабатывает выбранный API; если используется посредник, в обработке могут участвовать его поставщики моделей. Очистка дополнительно отправляет текст в выбранный API. Подробнее: [конфиденциальность](docs/PRIVACY.md).

## Сборка и проверки

Основная сборка требует полного Xcode и [XcodeGen](https://github.com/yonaskolb/XcodeGen). Проект генерируется из `project.yml`, а не хранится в Git.

```bash
brew install xcodegen
./scripts/build.sh                 # Debug через Xcode
./scripts/test.sh                  # XCTest для JotCore, нужен полный Xcode
open Jot.xcodeproj
```

Альтернативная локальная сборка требует Command Line Tools, `python3` и `rg`:

```bash
./scripts/build-clt.sh             # build/Jot.app, подпись ad-hoc
./scripts/verify-api-contract.sh   # локальные проверки API без ключей и сети моделей
```

`JOT_APP_PATH` задаёт другой путь результата сборки через CLT. Debug по умолчанию не требует Apple account. Для собственного сертификата передайте `DEVELOPMENT_TEAM` и `CODE_SIGN_IDENTITY` в `build.sh` или `JOT_SIGN_IDENTITY` в `build-clt.sh`.

Контрактные проверки используют синтетическое аудио, временные настройки и историю, подставной HTTP-транспорт. Они не подтверждают качество облачных моделей. Микрофон, горячие клавиши, вставка и реальный API проверяются отдельно в собранном приложении.

Если macOS показывает разрешённый Jot, но приложение не видит универсальный доступ, удалите старую запись и добавьте текущий `.app` заново. Разрешение ad-hoc сборки привязано к конкретному бинарнику и после пересборки может потребовать повторного добавления.

Debug-режим `--diagnose-permissions` печатает статусы разрешений и завершается до чтения ключей, истории и сетевых запросов. Проверяйте именно запуск приложения через LaunchServices: запуск из терминала может наследовать разрешения родителя.

```bash
open -n -W --stdout /tmp/jot-permissions.json build/Jot.app --args --diagnose-permissions
```

Повторные запуски дописывают JSON в файл — смотрите последнюю запись.

Релизы публикуются вручную. CI выполняет тесты и проверку сборки; релизного workflow нет. [Инструкция выпуска](docs/RELEASING.md) описывает подготовку ZIP без Apple Developer ID и отдельный путь подписанного DMG.
