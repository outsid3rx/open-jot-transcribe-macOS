# Jot

Голосовой ввод для macOS с Gemini, Polza и совместимыми API.

Автор форка — [Max Zernyaev](https://github.com/outsid3rx) · Apache 2.0
</div>

Проект — форк [оригинального Jot](https://github.com/google-gemini/jot-gemini-transcribe-macOS), созданного [Ammaar Reshi](https://x.com/ammaar). Эта версия добавляет выбор внешнего API, отдельную очистку текста и русский интерфейс. Это не официальный продукт Google.

Исходный код этой версии: [outsid3rx/open-jot-transcribe-macOS](https://github.com/outsid3rx/open-jot-transcribe-macOS). Оригинальные уведомления об авторских правах и лицензия сохранены.

Удерживайте `fn`, произнесите текст и отпустите клавишу — расшифровка появится в текущем приложении. Аудио сохраняется на диск до сетевого запроса. История позволяет просмотреть исходный и обработанный текст, прослушать запись и повторить запрос.

| Жест | Действие |
| --- | --- |
| Удерживать `fn` | Запись; отпускание запускает распознавание и вставку |
| `fn` + `Пробел` | Запись без удержания; нажатие `fn` завершает её |
| `Esc` | Отмена; длинные записи остаются в истории |

Клавиша меняется в настройках. Нужны разрешения macOS на микрофон и универсальный доступ для вставки текста.

## Начало работы

**Первый запуск:** сборка без Developer ID и нотариализации Apple может быть заблокирована macOS как приложение неизвестного разработчика. После попытки запуска откройте **«Системные настройки» → «Конфиденциальность и безопасность» → «Всё равно открыть»** и подтвердите открытие Jot. [Инструкция Apple](https://support.apple.com/ru-ru/102445).

1. Соберите приложение одним из способов ниже и откройте `build/Jot.app` для сборки через Command Line Tools.
2. Разрешите доступ к микрофону и универсальный доступ во время первоначальной настройки.
3. В разделе **«API и модели»** выберите провайдера, укажите базовый URL, точный идентификатор модели и сохраните ключ.
4. Выберите язык: «Авто» или код, например `ru`, если модель поддерживает явное указание языка.
5. Удерживайте клавишу диктовки и произнесите текст. Очистку включайте отдельно, указав текстовую модель.

## API и модели

В разделе **«API и модели»** выберите провайдера, введите **базовый URL**, **точное название модели** и сохраните её ключ. Список провайдеров задаёт начальные значения; URL и модель всегда редактируются вручную. Загрузки каталога и ограничения по фиксированному списку моделей нет. Ключи хранятся в Keychain отдельно для каждого провайдера и URL.

| Подключение | Базовый URL | Пример модели | Тип API |
| --- | --- | --- | --- |
| Google Gemini | `https://generativelanguage.googleapis.com` | `gemini-3.5-transcribe` | Gemini Interactions |
| Polza | `https://polza.ai/api/v1` | `openai/gpt-4o-mini-transcribe` | Транскрибация файла |
| Совместимый API | адрес провайдера, включая версию API | идентификатор провайдера | Транскрибация файла или чат с аудио |

URL указывается без `/audio/transcriptions` или `/chat/completions`: приложение добавляет нужный маршрут. HTTPS обязателен, HTTP допускается для localhost. Ключ не нужно помещать в URL. Наличие ключа не означает доступ к любой модели: фактическая проверка происходит при запросе.

Файловый адаптер отправляет WAV в `POST /audio/transcriptions`. Для Polza можно вручную указать:

- `openai/gpt-4o-mini-transcribe`
- `openai/gpt-4o-transcribe`
- `openai/whisper-large-v3-turbo`
- `mistralai/voxtral-mini-transcribe`

Эти четыре модели проверены на русском примере через Playground Polza: [отчёт](docs/design/polza-transcription-probe-2026-10-08.md). Запросы нового клиента проверены локально на подставных ответах. Полный сценарий из собранного Jot ещё требует проверки.

`mistralai/voxtral-small-24b-2507` использует **чат с аудио**. Реализован стандартный совместимый формат `input_audio: {data, format: "wav"}` через `POST /chat/completions`; точная совместимость этого формата с Polza для Small пока не подтверждена реальным запросом. Аудиочат может отвечать на сказанное вместо транскрибирования, поэтому файловая ASR-модель предпочтительнее для диктовки.

## Очистка и язык

**«Очищать и оформлять текст» выключено по умолчанию.** При включении выполняется отдельный текстовый запрос: убрать слова-паразиты, применить самокоррекции, исправить очевидные ошибки и оформить явные списки. Исходная расшифровка сохраняется до запроса. При ошибке, превышении времени или отклонении результата проверкой сходства возвращается исходный текст с локальными словарными заменами.

Выберите текстовую модель вручную. Можно использовать URL и ключ распознавания либо отдельный API. Пример идентификатора для Polza — `google/gemini-2.5-flash-lite`; его качество и скорость очистки в этой сборке ещё не измерены. Начальный лимит ожидания очистки — 1,5 секунды. Три отклонённых результата за сутки выключают текущую очистку с уведомлением. Сопоставление тона доступно как дополнительная настройка очистки.

Для файлового API доступны автоматическое определение языка и явный код, например `ru` или `en`. В режиме «Авто» поле `language` не отправляется; поддержка кодов зависит от модели. Gemini использует автоопределение.

В разделе **«Общие» → «Язык интерфейса»** можно выбрать **Русский** (по умолчанию) или **English**. Выбор сохраняется и применяется после перезапуска Jot. Язык интерфейса не меняет язык диктовки и не переводит расшифровки; системные диалоги macOS используют язык системы.

Gemini Smart обрабатывает речь внутри модели независимо от дополнительной очистки. Gemini Live доступен только для штатного Gemini Interactions с автоматическим языком и выключенной очисткой; сторонние модели работают после завершения записи.

## История и приватность

Обычный повтор сохраняет провайдера, URL, модель и язык исходной записи. Ошибка ключа или баланса одного API не останавливает очередь другого. **«С текущей моделью»** явно отправляет сохранённое аудио в выбранный сейчас API и создаёт новую запись, сохраняя старый результат. Отложенные запросы могут выполняться при запуске, восстановлении сети и изменении ключа.

У приложения нет собственного сервера и телеметрии. Данные обрабатывает выбранный провайдер; Polza выступает посредником к своим поставщикам моделей. Включение очистки передаёт расшифровку в выбранный текстовый API и добавляет стоимость запроса. Подробнее: [конфиденциальность](docs/PRIVACY.md).

## Сборка и проверки

Нужны macOS 14+. Основная сборка требует полного Xcode и [XcodeGen](https://github.com/yonaskolb/XcodeGen); `.xcodeproj` генерируется из `project.yml`. Для альтернативной локальной сборки достаточно Command Line Tools, `python3` и `rg`.

```bash
brew install xcodegen
./scripts/build.sh                  # Debug, подпись ad-hoc
./scripts/test.sh                   # XCTest для JotCore, нужен полный Xcode
./scripts/verify-api-contract.sh    # локальные проверки API, достаточно Command Line Tools
./scripts/build-clt.sh              # локальный Debug .app через Command Line Tools
open Jot.xcodeproj
```

Контрактные проверки используют синтетическое аудио, отдельные временные настройки/историю и подставной HTTP-транспорт. Они не обращаются к облачным моделям и Keychain. Полная проверка микрофона, горячих клавиш и вставки выполняется в собранном приложении.

`build-clt.sh` — вспомогательная локальная сборка без XcodeGen: компилирует App, переносит ресурсы и подписывает `build/Jot.app` ad-hoc. Нужны `swift`, `python3` и `rg`; приложение не запускается и не устанавливается автоматически. Основной путь Xcode остаётся `build.sh`.

У локальной ad-hoc сборки подпись привязана к конкретному бинарнику. Если macOS показывает разрешённый Jot, но приложение не видит универсальный доступ, удалите прежнюю запись Jot в системных настройках и добавьте текущий `build/Jot.app` заново. Особенно это важно после официальной версии с тем же bundle ID. После пересборки разрешение может потребовать повторного добавления. Для подписи своим сертификатом задайте `JOT_SIGN_IDENTITY` при запуске `build-clt.sh`.

Диагностика локальной Debug-сборки: `Jot.app/Contents/MacOS/Jot --diagnose-permissions` печатает статусы и завершается до чтения ключей, истории и сетевых запросов. Для проверки именно разрешения приложения запускайте этот режим через LaunchServices (`open -n -W --stdout /tmp/jot-permissions.json build/Jot.app --args --diagnose-permissions`): запуск из терминала может наследовать разрешения родительского процесса. Повторные проверки дописываются в файл; смотрите последнюю JSON-запись.

Debug по умолчанию не требует Apple account или сертификата. Для подписи сертификатом Apple передайте свой `DEVELOPMENT_TEAM` и `CODE_SIGN_IDENTITY` в `build.sh` либо `JOT_SIGN_IDENTITY` в `build-clt.sh`. Release использует Developer ID и отдельный `scripts/release.sh`.
