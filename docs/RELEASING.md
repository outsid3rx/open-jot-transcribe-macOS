# Публикация релизов

Релизы этого форка публикует автор вручную через GitHub Releases. Релизного workflow нет: `.github/workflows/ci.yml` запускает тесты JotCore и проверяет сборку приложения при push в `main` и pull request. Создание тега не публикует релиз автоматически.

## Подготовка сборки без Apple Developer ID

1. Укажите версию и номер сборки в `project.yml`: `MARKETING_VERSION` и `CURRENT_PROJECT_VERSION`.
2. Выполните `./scripts/verify-api-contract.sh`. На машине с полным Xcode также выполните `./scripts/test.sh`.
3. Соберите приложение: `./scripts/build-clt.sh`. Результат — `build/Jot.app`, подписанный ad-hoc. Платная учётная запись Apple Developer не требуется.
4. Вручную проверьте разрешения, запись, выбранный API, вставку текста и переключение языка интерфейса после перезапуска. Локальные контрактные тесты не подтверждают работу облачных моделей.
5. Создайте ZIP, сохранив структуру `.app`:

```bash
jot_version=$(awk '/MARKETING_VERSION/ {gsub(/"/, "", $2); print $2; exit}' project.yml)
jot_arch=$(uname -m)
ditto -c -k --sequesterRsrc --keepParent build/Jot.app "build/Jot-$jot_version-macOS-$jot_arch.zip"
```

Архив содержит сборку для архитектуры машины, на которой она создана, а не универсальный бинарник. Каталог `build/` не добавляется в Git.

## Загрузка на GitHub

После отправки коммитов в репозиторий создайте релиз в [GitHub Releases этого форка](https://github.com/outsid3rx/open-jot-transcribe-macOS/releases), выберите тег соответствующей версии, приложите ZIP и опишите изменения. В описании укажите архитектуру, macOS 14+ и отсутствие подписи Developer ID и нотариализации Apple.

Добавьте инструкцию первого запуска: если macOS блокирует Jot как приложение неизвестного разработчика, после попытки запуска откройте «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть». [Инструкция Apple](https://support.apple.com/ru-ru/102445). Доступ к микрофону и универсальный доступ выдаются отдельно. После пересборки ad-hoc разрешения могут потребовать повторного добавления приложения.

## Выпуск с сертификатом Apple

`scripts/release.sh` сохранён как отдельный необязательный путь для подписанного и нотариализированного DMG. Он требует полного Xcode, подходящих сертификатов, настроек команды и профиля `notarytool`; параметры подписи исходного проекта необходимо адаптировать к собственной команде. Для текущего выпуска без Apple Developer ID используйте `build-clt.sh` и ручную загрузку ZIP.
