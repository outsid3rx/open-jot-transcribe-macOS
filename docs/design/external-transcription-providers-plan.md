# Поддержка внешних API для диктовки Jot

Статус: шесть пользовательских требований реализованы в коде; приёмка собранного приложения остаётся открытой. Дата: 8 октября 2026 года.

## Фактическая реализация

| Требование | Выполнено |
| --- | --- |
| Внешнее распознавание | Общая цепочка для Gemini, файлового `audio/transcriptions` и стандартного аудиочата `chat/completions` |
| Очистка | Отдельная выбранная текстовая модель, выключена по умолчанию; raw сохраняется до очистки, её сбои возвращают исходный текст |
| Провайдер, URL и модели | Редактируемые пресеты Gemini / Polza / совместимый API; URL и идентификаторы обеих моделей вводятся текстом; отдельный API очистки по желанию |
| Язык | Авто либо явный код для совместимого API; Gemini — авто; выбор сохраняется с записью |
| Язык интерфейса | Русский по умолчанию, опционально English в общих настройках; после перезапуска локализованы окна, меню, HUD, ошибки, словарь и onboarding; ресурсы ru/en |
| Очистка кода | Удалены старые дубли настроек URL/моделей, заглушки, неиспользуемый поиск модели в onboarding и зависимость KeyboardShortcuts |

`TranscriptionConfiguration` хранит два выбранных API; полная копия сохраняется в `SessionMeta`. Это заменяет предложенные ниже отдельно управляемые UUID-профили. Keychain привязан к провайдеру и базовому URL; стандартный ключ Gemini сохранён. Старые записи получают неизменяемую исходную конфигурацию миграции.

Каталог и фиксированный список моделей не ограничивают ручной ввод. В этом варианте не добавлены загрузка/кэш каталога и редактор набора профилей: последнее уточнение пользователя сделало приоритетом текстовые URL и модели. Обычный повтор использует старую конфигурацию. «С текущей моделью» создаёт новую запись с текущими настройками, сохраняя старый результат.

Проверки: ядро компилируется, App проходит проверку типов; `scripts/verify-api-contract.sh` выполняет 18 локальных проверок на URLProtocol с временными настройками/историей, без Keychain и платных запросов. Через `scripts/build-clt.sh` собран `build/Jot.app`, проверены ресурсы и подпись ad-hoc. Полный XCTest здесь не запускается из-за отсутствия модуля XCTest в Command Line Tools. Сборка через полный Xcode/XcodeGen и проверка интерфейса, микрофона и вставки остаются отдельной приёмкой. После исправления подписи разрешение универсального доступа проверено через диагностический запуск в LaunchServices.

Четыре файловые модели проверены в Playground. Новый клиент ещё не проверен с настоящим ключом. JSON аудиочата реализован, но контракт Polza для Voxtral Small пока не подтверждён. Качество и скорость очистки выбранной дешёвой моделью и достаточность лимита 1,5 секунды также требуют измерения.

Ниже сохранены исходное исследование, проектные варианты и критерии приёмки. При расхождении архитектурных предложений с таблицей выше фактическая реализация описана в таблице.

Предварительная проверка: [четыре файловые модели успешно распознали один русский WAV через Playground](polza-transcription-probe-2026-10-08.md). Это закрывает проверку доступности этих моделей на одном примере, но не весь P0: прямой API-контракт, Voxtral Small, ограничения и ошибки ещё нужно проверить до адаптации приложения.

Jot должен позволять выбирать провайдера, API-ключ и модель отдельно от механики записи и вставки текста. Первый выпуск добавляет Polza с тремя исходно запрошенными моделями OpenAI и двумя моделями Voxtral из таблицы ниже, сохраняет действующий Gemini и позволяет настраивать другие API с совместимым контрактом. По последнему уточнению пользователя модели OpenAI возвращены в обязательные пресеты.

Для первой реализации файловой диктовки предлагается проверенный GPT-4o Mini Transcribe; пользователь может выбрать другую модель. Small также входит в объём реализации, но использует отдельный маршрут чата с аудио и требует проверки поведения транскрибации. Совместимость протокола и качество диктовки проверяются отдельно.

## Обязательные требования пользователя

| Шаг | Требование | Результат |
| --- | --- | --- |
| 1 | Реализовать отправку запросов выбранным моделям | Запись отправляется через соответствующий адаптер, текст возвращается в общую цепочку Jot |
| 2 | Реализовать дополнительную очистку с переключателем | «Очищать и оформлять текст» выключено по умолчанию; при выключении дополнительный запрос не выполняется |
| 3 | Разрешить задавать API URL и выбирать две модели | Модель транскрибации обязательна, модель очистки нужна только при включённой очистке; адрес API редактируется |
| 4 | Разрешить задавать язык транскрибации | «Автоматически» по умолчанию, явный выбор русского и других поддерживаемых языков |
| 5 | Русский по умолчанию с возможностью вернуть английский | Язык интерфейса выбирается в общих настройках и применяется после перезапуска; язык диктовки сохраняется отдельно |
| 6 | Почистить код и удалить неактуальные пункты настроек | Удалены дубли новой конфигурации, неиспользуемые пути и зависимости; пользовательские данные перенесены безопасно |

Выполнение этих требований входит в объём первого выпуска. Приведённые ниже этапы раскрывают реализацию и проверки; изменение только документации не считается выполнением шагов.

Voxtral Small найден отдельно в разделе «Чат»: контекст 32 768 токенов и максимальный ответ 26 214 токенов. После выбора доступны max tokens, temperature и другие настройки чата. Обработка Small остаётся отдельным маршрутом и не включается в список обычных ASR только из-за наличия аудиовхода. Возможность отправки аудио через Polza и её контракт проверяются на P0.

Для Polza предусмотреть обновление списка моделей из каталога и фильтрацию по маршруту `/audio/transcriptions`; аудиочат показывать отдельно. Пять целевых моделей остаются обязательными проверяемыми пресетами, остальные ASR могут использовать общий адаптер после подтверждения контракта. Офлайн сохраняется последний каталог и встроенные пресеты. Поддержка всех тринадцати не объявляется по одному присутствию в списке.

Публичный `/api/v1/models` успешно читается без API-ключа, поэтому ответ 200 этого маршрута подтверждает доступность каталога, но не валидность пользовательского ключа. Для проверки ключа на P0 выбрать документированный защищённый маршрут; если отдельного маршрута нет, отдельно показывать наличие ключа и успешность явно запущенной тестовой транскрибации.

[Инструкция Polza для распознавания речи](https://polza.ai/collections/stt) задаёт базовый адрес `https://polza.ai/api/v1`, Bearer-авторизацию и multipart-поля `file` и `model`. [Документация Mistral](https://docs.mistral.ai/studio/audio/speech_to_text/offline_transcription) разделяет файловую транскрибацию Mini и чат с аудио Small. Идентификаторы Mistral напрямую не заменяют идентификаторы Polza.

Для Small нельзя переносить формат `input_audio` из прямого Mistral API без проверки: пример Mistral использует строку base64, а совместимый шлюз может требовать другую структуру. Точные поддерживаемые форматы аудио, поля, пределы размера и длительности фиксируются на этапе проверки контракта. Ни SSE, ни WebSocket для запланированных моделей через Polza в первом выпуске не обещаются.

## Основа проекта до изменений

`TranscriptionServicing` уже отделяет координатор от реализации распознавания. Однако `GeminiTranscriptionService` объединяет транспорт, FLAC, повторы, словарь и форматирование. `DictationController`, onboarding и Settings напрямую создают `GeminiClient` и проверяют единственный Gemini-ключ.

У `SessionMeta` есть строка `modelID`, но нет сохранённого профиля запроса. `RetryQueue` и `RecoveryScanner` вызывают общий сервис с текущими настройками, поэтому после добавления провайдеров без изменения метаданных старая запись могла бы уйти в другой сервис. Это нужно исправить до подключения новых адаптеров.

## План работ

| Этап | Изменение | Результат и условие завершения |
| --- | --- | --- |
| P0 | Проверить контракты всех целевых моделей Polza | Установлены формы запросов, ответов, ошибки, форматы и ограничения; успешный запрос не подменяется присутствием модели в каталоге |
| P1 | Ввести профили провайдеров, моделей и ключей | Редактируемый API URL, обязательная модель транскрибации, необязательная модель очистки и соответствующие ключи |
| P2 | Сохранять конфигурацию запроса вместе с сеансом | Смена настроек не меняет текущую диктовку, Retry или восстановление |
| P3 | Добавить адаптер файловой транскрибации | GPT-4o Mini, GPT-4o, Whisper Turbo и Voxtral Mini отправляются через multipart и работают без Gemini-ключа |
| P4 | Добавить адаптер чата с аудио | Small получает аудио и возвращает расшифровку; обрезанные и явно некорректные ответы не вставляются |
| P5 | Реализовать дополнительную очистку | Переключатель выключен по умолчанию; включённая очистка убирает слова-паразиты, применяет самокоррекции и оформляет списки |
| P6 | Реализовать настройки API, моделей и языка | Задаются URL, ключ, две модели и язык транскрибации; ограничения выбранной модели объяснены в интерфейсе |
| P7 | Адаптировать ошибки, очередь и восстановление | Ошибка одного провайдера не блокирует записи другого; отсутствующий профиль не приводит к скрытой смене сервиса |
| P8 | Перевести приложение на русский | Переведены все собственные пользовательские поверхности, включая onboarding, HUD, меню и ошибки |
| P9 | Почистить код и устаревшие настройки | Удалены дубли новой конфигурации и неиспользуемый код, зависимости и пользовательские пункты; миграция сохраняет действующие данные |
| P10 | Проверить интеграцию и обновить документацию | Пройдены автоматические проверки и ручная диктовка, выбор языка и русская локализация; описаны фактические маршруты данных |

Зависимости этапов: P0 → P1 → P2; затем P3 и P4; P5 использует общую цепочку после ASR; P6 и P7 завершают интеграцию. P8 переводит пользовательские тексты, включая новые настройки. P9 удаляет устаревшие пути и проверяет оставшиеся локализованные поверхности; P10 закрывает выпуск. Очистку можно проверить с первым файловым адаптером, не дожидаясь аудиочата Small. Это порядок реализации, а не выполненные задачи.

## Контракт провайдеров

Провайдер, API-протокол и модель — разные сущности. Один Polza-профиль содержит ключ, но поддерживает два протокола запросов.

Предлагаемые типы:

- `ProviderProfile`: стабильный идентификатор, название, базовый URL, ссылка на запись Keychain и настройки проверки соединения.
- `ModelDescriptor`: точный `modelID`, маршрут `geminiInteractions`, `geminiLegacy`, `audioTranscriptions` или `audioChatCompletions`, подтверждённые возможности и ограничения.
- `TranscriptionSelection`: обязательные профиль и модель транскрибации, выбранный язык, `cleanupEnabled = false` по умолчанию и необязательная конфигурация очистки.
- `CleanupSelection`: выбранные профиль API и текстовая модель, политика очистки и тона; требуется только при `cleanupEnabled = true`.
- `TranscriptionSnapshot`: неизменяемая конфигурация конкретного сеанса без ключа, включая адрес, маршрут, параметры и конфигурацию дополнительной обработки.
- `TranscriptionRequest`: CAF-файл, длительность, контекст приложения и snapshot.
- `TranscriptionRouter`: реализация `TranscriptionServicing`, выбирающая адаптер по snapshot.
- `TextFormattingServicing`: отдельный контракт дополнительной обработки готового текста.

`TranscriptionServicing` принимает `TranscriptionRequest`; обновляются координатор, очередь, восстановление и тестовые сервисы. Gemini сохраняется как отдельный адаптер с действующими протоколами и поведением. `FormattingPolicy` перестаёт ссылаться на вложенный тип `GeminiClient.TranscriptionMode`.

Схема работы:

```text
Выбор профиля и модели → snapshot при начале диктовки → CAF на диске
    ↓
TranscriptionRouter
    ├─ Gemini → interactions / legacy
    ├─ Polza GPT / Whisper / Voxtral Mini → multipart /audio/transcriptions
    └─ Polza Small → JSON /chat/completions с аудио
    ↓
Текст распознавания → [очистка, только если включена] → словарные замены
    ↓
History → действующий механизм вставки

Retry / восстановление → сохранённый snapshot → тот же router
```

Каталог возможностей должен различать native Smart, live audio, подсказки словаря, язык, формат ответа и ограничения входа. Неизвестная возможность считается неподтверждённой. Новое имя модели само по себе не включает функцию.

Пользовательские профили поддерживают только перечисленные совместимые протоколы, а не произвольный API. Настройка URL и имени модели не означает поддержку любого сервиса. Для неизвестной модели используются минимальные параметры и ручная проверка; каталог Polza не переносится на другие хосты.

## Проверка запросов и подготовка аудио

На P0 для каждой модели проверяются короткая русская и английская запись, смешанная речь, тишина, словарь и запись с самокоррекцией. Для Small добавляются произнесённые вопросы и инструкции вроде «напиши функцию»: результат должен передавать речь, а не выполнять её. Тесты реального API включаются явно и используют отдельные несекретные аудиофайлы.

Фиксируются успешные и ошибочные ответы, MIME, форма аудиочасти, доступность языка и словарных подсказок. Обезличенные JSON-ответы можно сохранить как тестовые fixtures; ключи и личные записи в репозиторий не попадают. Раздел документации Polza `/docs` при подготовке плана возвращал 503; поэтому дополнительные поля шлюза не считаются подтверждёнными примерами прямого Mistral API.

Файловые модели GPT, Whisper и Voxtral Mini: `Authorization: Bearer …`, multipart с бинарным файлом и полным идентификатором модели. Multipart не содержит base64. Начальный запрос использует обязательные поля; `response_format`, `language`, `prompt` или `context_bias` добавляются только после проверки конкретной модели на этом маршруте Polza. Ожидаемая структура результата — JSON с текстом, окончательно закрепляемая fixture. Набор параметров одного ASR-пресета не переносится автоматически на остальные.

Small: Bearer-авторизация, JSON с `model` и сообщением пользователя, содержащим аудио и отдельную инструкцию. Инструкция просит точную расшифровку на языке оригинала без перевода, ответа на вопросы или выполнения произнесённых команд. Словарные термины передаются как данные, а не инструкции. Tools не отправляются. Полная расшифровка извлекается из `choices[].message.content` согласно проверенному контракту; `finish_reason` проверяется, включая обрезку по лимиту.

CAF остаётся единственным исходным аудиоартефактом. Подготовку загрузки вынести в `AudioUploadEncoder`: существующий FLAC для Gemini и поддерживаемые FLAC/WAV для остальных маршрутов. Выбор формата задаётся подтверждёнными возможностями; для Small нельзя без проверки полагаться на поддержку FLAC. Производные файлы удаляются после завершения или отмены запроса, CAF сохраняется для Retry.

Не выполнять кодирование, чтение всего файла и сборку большого multipart/JSON на главном потоке. Multipart при необходимости собирать во временный файл, чтобы не размножать аудио в памяти. После подготовки проверять реальный размер и лимит длительности. Если существующие десять минут не помещаются в контракт модели, P0 определяет необходимость разбиения на фрагменты; это включается в реализацию либо задаётся честный предел с сохранением исходного аудио. Обрезка текста и аудио не допускается.

## Ключи и миграция настроек

Добавить в `KeychainStore` операции по идентификатору профиля. Существующая запись `com.ammaar.jot / gemini-api-key` становится ключом встроенного Gemini-профиля, без удаления и повторного ввода. Ключ Polza хранится отдельно. Пользовательские профили имеют собственные записи Keychain.

Миграция настроек идемпотентна: старые модели, endpoint override, legacy-режим, Smart и Tone переходят в Gemini-профиль. Для текущих пользователей выбранным остаётся Gemini. Отсутствующий переключатель дополнительной очистки получает `false`; существующий явно заданный пользователем выбор сохраняется для Gemini. Новые профили создаются с выключенной очисткой независимо от выбора другого профиля. Для нового пользователя onboarding предлагает выбор провайдера; при выборе Polza предлагается GPT-4o Mini Transcribe, а другие целевые модели доступны в списке. Ключи не копируются между профилями.

Base URL включает API-префикс: например, `https://polza.ai/api/v1`. Адаптер добавляет относительный путь без повторного `/api/v1`. Идентификатор `mistralai/…` передаётся значением поля, а не частью URL.

Настройки удалённого API требуют корректного HTTPS-адреса без ключа в URL; локальный HTTP может быть предусмотрен для localhost. Ключ связан с профилем и адресом назначения. Смена origin требует новой явной привязки ключа. Авторизованные запросы не перенаправляются на другой origin с сохранением credentials. Это часть корректного разделения провайдеров.

Ключ считывается для конкретного запроса и не меняется между его автоматическими попытками. В snapshot, SQLite, JSON, сообщениях ошибок и логах ключей нет.

## Сеансы и повторная обработка

Snapshot записывается при начале сеанса до сетевого вызова. Он включает профиль, маршрут, модель, адрес и фактические параметры обработки; изменения в Settings применяются к следующей диктовке.

В `SessionMeta` добавить версионированный snapshot и сведения о фактически использованных распознавателе и форматировщике. При необходимости расширить SQLite-индекс миграцией. Новые optional-поля не должны ломать чтение старых JSON.

Для старых записей без snapshot выполнить явную миграцию в текущую перенесённую конфигурацию Gemini и сохранить результат один раз. Уже готовые тексты не отправляются повторно. Если для прерванной старой записи нельзя восстановить исходное имя модели, History указывает, что используется мигрированная конфигурация; новое имя не выдаётся за исторически использованное.

Обычный Retry использует сохранённый snapshot. При удалённом профиле, отсутствующем ключе или недоступной модели запись получает понятную причину ожидания; автоматической подстановки Gemini или другого провайдера нет. Отдельное действие «Повторить с другой моделью» создаёт новую попытку с явно выбранной конфигурацией и сохраняет связь с исходной записью. Исходный успешный текст не затирается неудачной попыткой.

Результаты фоновых повторов и восстановления остаются в History. Новые провайдеры не меняют действующую защиту фокуса и Secure Input.

## Обработка текста и возможности интерфейса

Native Smart Gemini остаётся его собственной возможностью. Для файловых моделей GPT, Whisper и Voxtral Mini не предполагается эквивалент Gemini Smart. У Small инструкция транскрибирования также не считается независимой гарантией «точной записи» или безопасной умной обработки.

Дополнительная очистка имеет отдельный переключатель «Очищать и оформлять текст» и выключена по умолчанию. При выключении не выполняются запросы форматировщика, не требуется его модель или ключ и не показываются ошибки отсутствующей конфигурации очистки. Сохранённый выбор второй модели может оставаться в настройках для следующего включения. Native Smart Gemini не включает этот переключатель и не запускает второй запрос автоматически.

Дополнительная обработка готового текста выделяется из `GeminiTranscriptionService`. Для Gemini сохраняется существующий форматировщик. Для Polza используется отдельная выбранная текстовая модель через `/chat/completions`; она не обязана совпадать с аудиомоделью. Это позволяет сочетать GPT-4o Mini Transcribe, Whisper или Voxtral Mini с дешёвым форматировщиком полностью через Polza, без Gemini-ключа. Small остаётся одним из вариантов, но аудиовозможности на этом этапе не нужны. При выборе Small для обоих этапов выполняются два отдельных запроса; второй не обязателен.

Политика различает точную расшифровку, удаление слов-паразитов/самокоррекции и согласование тона. Для внешнего API Smart/Tone доступны только при настроенном обработчике текста; без него интерфейс показывает обычную транскрибацию. Переключение на Polza не должно молча запускать Google-форматирование, даже если раньше Tone был включён для Gemini.

Перед дополнительной обработкой сохраняется текст первого этапа. `ValidationGate` сравнивает его с обработанным результатом; таймаут, ошибка или отклонение возвращают исходный текст. Бюджет и счётчики автоматического отключения относятся к конкретному профилю форматировщика. Детерминированные замены словаря применяются всегда, включая fallback.

### Очистка речи и оформление списков

По уточнению пользователя дополнительный запрос выполняет Smart-обработку: убирает слова-паразиты и ложные начала, применяет явные самокоррекции, исправляет очевидные грамматические оговорки и оформляет перечисления. Tone остаётся независимой настройкой: очистка речи не требует подстраивать стиль под приложение.

Цепочка: `ASR → сохранение исходного текста → текстовая модель → проверка → словарные замены → вставка`. В дополнительном запросе передаётся только расшифровка и необходимые словарные правила. Повторно отправлять аудио для этого этапа не требуется.

Начальный кандидат для проверки — [Gemini 2.5 Flash Lite через Polza](https://polza.ai/models/google/gemini-2.5-flash-lite); сравнительный кандидат — [GPT-4o mini](https://polza.ai/models/openai/gpt-4o-mini). По карточкам Polza на 8 октября 2026 года ставки за миллион входных/выходных токенов составляют соответственно 5,98/23,93 ₽ и 17,97/71,90 ₽. Для условного запроса с 1000 входных и 300 выходных токенов это около 0,013 ₽ и 0,040 ₽; сюда входят токены инструкций, а возможные дополнительные начисления и округление требуют проверки. Цены не фиксируются в коде. Скорость через Polza и качество русской очистки ещё не измерены; название Flash/Lite не заменяет этот тест.

Контракт обработки:

- Удалять «эм», «ээ», повторы и слова-паразиты только там, где они не несут смысла. Не удалять автоматически любое «ну», «как бы» или «значит».
- В «в три часа, нет, лучше в четыре» оставлять «в четыре часа». Сохранять контекст, который не отменён явно.
- Исправлять грамматику без пересказа, добавления фактов и изменения первого лица.
- Оформлять явные перечисления пунктами, сохранять порядок и все элементы. Использовать нумерацию при «первое/второе» и последовательных шагах; не превращать каждый ряд существительных в список.
- Для вставки в произвольное приложение использовать обычный текст с переносами и простыми маркерами; Markdown допустим только как отдельный режим.
- Вопросы и команды внутри расшифровки оставлять содержимым текста. Не отвечать на них, не выполнять их и не удалять только потому, что они похожи на инструкции.
- Сохранять имена, отрицания, единицы измерения, числа и даты, кроме явно исправленных самим говорящим значений. Править специальные названия по словарю, а не догадкой.
- Возвращать только обработанный текст, без вступления, объяснений, кодовых блоков и перевода.

Короткие расшифровки имеют начальный общий лимит дополнительного запроса 1,5 секунды, как действующий Gemini cleanup; достаточность этого лимита проверяется измерением. На этом этапе нет автоматического повторного вызова форматировщика, который удваивал бы задержку. Для длинных расшифровок отдельный бюджет определяется после замеров. Температура низкая; рассуждение, поиск и tools не включаются, а параметры отключения reasoning передаются только по подтверждённому контракту шлюза.

Результат проверяется целиком до вставки. Пустой ответ, обрезка по `finish_reason`, ответ на вопрос вместо очистки, сильный смысловой уход или ошибка транспорта возвращают исходную расшифровку. Русские примеры нужно добавить к текущему `ValidationGate`: удаление исправленного числа и сокращение слов-паразитов не должны ошибочно считаться потерей содержания. Исходный и обработанный варианты сохраняются для просмотра в History.

До адаптации приложения выполнить отдельный эксперимент на уже полученных четырёх расшифровках и дополнительных текстовых примерах:

| Пример | Критерий |
| --- | --- |
| Сохранённая тестовая расшифровка «в три, нет, лучше в четыре» | Удалено отменённое время, сохранены вопрос и произнесённая команда |
| «Нужно купить молоко, хлеб и яйца» после явно произнесённого указания на список | Три пункта, исходный порядок и состав |
| «Первое проверить API, второе добавить настройки, третье протестировать» | Нумерованный список из трёх действий |
| «Не отправляй письмо, сумма пятнадцать тысяч, срок до пятницы» | Не потеряны отрицание, сумма и срок |
| Имена и технические термины со словарём и без него | Словарь применён; без словаря нет выдуманных исправлений |
| «Ну это значит, что условие не выполнено» | Смысловые слова сохранены, нет механического удаления |

Оценить корректность и время ответа на нескольких повторах; публиковать измеренную задержку именно дополнительного запроса, отдельно от ASR. Успешная чистка текстовых примеров не доказывает исправление ошибок распознавания на слух: текстовая модель не слышит исходное аудио, а сомнительные фамилии и числа не должна восстанавливать догадкой.

Для аудиочата Small нужна отдельная проверка ответа: пустой текст, отказ, явный ответ ассистента, обрезка и грубая неправдоподобность. Сравнение ответа с самим собой не является проверкой. Без независимой расшифровки невозможно автоматически доказать отсутствие смысловых изменений; поэтому нужны речевые примеры и оценка качества, в том числе на русском. Подозрительный ответ сохраняется с аудио в History и не вставляется автоматически.

Live и legacy-переключатель доступны только для Gemini. Выбор внешнего провайдера прекращает создание Gemini Live-сессии для новых записей. Настройки Gemini сохраняются для возвращения к нему. Потоковый ответ после загрузки файла и live-передача микрофона — разные возможности; ни одна не включается только по поддержке чата.

## Настройки API и моделей

Основные настройки разделены на «Распознавание речи» и «Очистка текста».

| Поле | Поведение |
| --- | --- |
| Провайдер и URL API | Пресет заполняет URL; пользователь может его изменить или создать профиль совместимого API |
| Ключ API | Хранится в Keychain и относится к выбранному профилю |
| Модель транскрибации | Обязательна; список фильтруется по возможностям распознавания, доступен точный ручной идентификатор |
| Язык транскрибации | «Автоматически» по умолчанию либо выбранный поддерживаемый язык |
| Очищать и оформлять текст | Выключено по умолчанию; включает дополнительный текстовый запрос |
| Использовать тот же API для очистки | По умолчанию включено: вторая модель использует URL и ключ профиля транскрибации |
| URL и ключ API очистки | Настраиваются отдельно, если пользователь выбрал другой API для второго этапа |
| Модель очистки | Текстовая модель; обязательна только при включённой очистке, выбирается независимо от ASR |

Для обычного сценария Polza достаточно одного URL `https://polza.ai/api/v1`, одного ключа и двух независимых выбранных моделей. Второй URL не обязателен. Выбор очистки из того же API сохраняет ссылку на профиль, а не копию ключа. API-протокол и дополнительные поля остаются в продвинутых настройках.

Списки моделей распознавания и очистки загружаются из соответствующих профилей, если API предоставляет каталог; при его отсутствии доступны встроенные пресеты и ручной идентификатор. Смена адреса обновляет каталог и статус проверки только затронутого профиля. Включение очистки требует пригодной конфигурации второй модели; отсутствующая модель сопровождается русской подсказкой и не должна молча включать другой сервис.

Onboarding запрашивает обязательные URL/ключ/модель распознавания; очистка не является условием завершения настройки. Сообщения HUD перестают требовать именно Gemini-ключ. History показывает провайдера и модель. Состояние «ключ проверен» отличается от «модель успешно распознала тестовую запись».

## Язык транскрибации

Выбранный язык относится к распознаванию речи, а не к языку интерфейса или переводу текста. По умолчанию используется автоматическое определение; русский выбирается явно как `ru`. Другие языки показываются по подтверждённым возможностям модели, с понятными названиями в русском интерфейсе.

В режиме «Автоматически» адаптер не отправляет фиктивное `language=auto`, если контракт ожидает отсутствие параметра. В явном режиме язык преобразуется в параметр конкретного API; неподдерживаемое значение не отправляется молча. Если модель допускает только автоопределение, это видно в настройках; прежний выбор языка не сбрасывается незаметно при смене модели.

Поддержку `language` проверить на P0 отдельно для каждого файлового ASR-пресета. Для Gemini проверить совместимость ограничения языка с native Smart: `language_codes` нельзя считать универсальным параметром или добавлять без проверки. Инструкция языку в аудиочате не приравнивается к поддержке специального API-параметра.

Язык и эффективные параметры входят в snapshot записи и применяются при Retry. Изменение языка во время диктовки относится к следующему сеансу. Очистка сохраняет язык исходной расшифровки и не переводит её на русский только потому, что интерфейс русский. Смешанная русско-английская речь не должна терять названия и идентификаторы.

## Русский интерфейс

Русский перевод входит в первый выпуск, включая новые настройки провайдеров. Перевести собственные окна и элементы Jot: меню строки состояния, onboarding и пробную диктовку, настройки, History и Dictionary, HUD, подсказки горячих клавиш, уведомления восстановления, ошибки сети/баланса/ключа/модели, подтверждения удаления, подписи элементов доступности и About.

Пользовательские строки находятся в ресурсах `JotCore/Sources/Resources/{ru,en}.lproj/Localizable.strings`. Русский выбран по умолчанию независимо от языка macOS; English доступен в общих настройках. Сохранённый выбор применяется при следующем запуске, чтобы меню, статические подсказки и окна использовали один язык. Описания разрешений локализованы через InfoPlist-ресурсы; системные диалоги отображает сама macOS.

Строки для пользователя из JotCore, например coaching hints, причины Secure Input и смены микрофона, преобразовать в типизированные сообщения с параметрами и отображать русским текстом в App. Сообщения диагностики, API-идентификаторы, bundle ID, URL-схема, ключи UserDefaults/Keychain и машинные коды ошибок не переводятся. Тексты расшифровок, пользовательские записи словаря и названия моделей сохраняются как данные.

Проверить русские окончания числительных для количества записей и минут, формат даты/времени, длинные строки в компактном HUD и клавиатурные обозначения. В интерфейсе не должны оставаться собственные английские подсказки; имена брендов, моделей, приложений и исходные сообщения внешнего API могут сохранять оригинальное написание. Локализация интерфейса не меняет язык диктовки или поведение промптов очистки.

## Очистка кода и неактуальных настроек

После реализации новой конфигурации удалить старые параллельные источники настроек и неиспользуемые пути. Настройки должны управлять действующим поведением: одна обязательная модель распознавания, один выключенный по умолчанию переключатель очистки, необязательная вторая модель, API-профили и язык.

| Текущая область | Действие |
| --- | --- |
| Старые глобальные `endpointOverride`, `transcribeModelOverride`, `cleanupModelOverride` | Перенести значения в профили API и выбор двух моделей; убрать дублирующие поля Advanced и чтение старых ключей из обычного runtime |
| Раздел, требующий именно Gemini API key | Заменить общими настройками выбранного API; отдельные ключи провайдеров остаются в профилях |
| Существующий дополнительный Tone/cleanup-переключатель | Свести к новой конфигурации очистки; отдельная настройка тона допускается внутри включённого этапа без второго дублирующего выключателя |
| Gemini native Smart, Live и legacy endpoint | Оставить только в настройках соответствующего Gemini-профиля, если путь поддерживается; не показывать их как общие рабочие функции Polza |
| Старый legacy endpoint после проверки P0 | Если он признан более не поддерживаемым или ненужным, удалить вместе с соответствующей настройкой и ветками; действующий fallback не удаляется лишь из-за названия legacy |
| `StubTranscriptionService`, `StubClipboardInserter` | В текущем дереве найдены только объявления; проверить после интеграции и удалить неиспользуемые заглушки, сохранив реальные тестовые fakes |
| SPM-зависимость `KeyboardShortcuts` | В текущем App и JotCore нет использования; проверить итоговое дерево и удалить неиспользуемую зависимость из `Package.swift` |

Объединить повторяющиеся проверки ключа, готовности выбранного API, обработки ошибок и очистки там, где они уже заменены общими сервисами. Удалить недостижимые ветки, мёртвые уведомления/подписки, отладочные настройки без потребителей и комментарии о давно завершённых этапах. Актуальные параметры микрофона, горячих клавиш, хранения аудио, звуков и HUD сохраняются; экспериментальная функция не считается неактуальной только по своему статусу.

Код миграций, включая перенос старого `smartFormatting`, отделить от обычного runtime. Совместимость с существующими установками и метаданными не удаляется как «старый код», пока она нужна для обновления. Старые значения настроек очищаются только после успешного переноса; ключи Keychain, история, записи и словарь не теряются. Если удаляется настройка, её текущее значение явно преобразуется в новое поведение или объясняется пользователю.

После удаления каждого пути проверить отсутствие потребителей: поля UI, обработчики событий, URL-команды, параметры в snapshot, миграции, тесты, документация и ресурсы перевода. Удалить осиротевшие локализованные строки, сохранив необходимые миграционные fixtures. Задача завершается сборкой, тестами и ручной проверкой, что оставшиеся пункты настроек влияют на приложение.

## Ошибки и политика повторов

Повторы общие по смыслу, но разбор HTTP-ответов остаётся в адаптере. Gemini-правила нельзя механически применять к другому сервису.

| Ситуация | Планируемое поведение |
| --- | --- |
| Нет сети | Сохранить CAF и snapshot, поставить в очередь |
| Таймаут, сбой соединения, 5xx | Одна ограниченная автоматическая попытка тем же провайдером, затем History/очередь |
| 401 | Сообщить о ключе выбранного профиля, сохранить запись |
| 402 Polza | Отдельная ошибка `insufficientBalance`, предложить пополнение; не выдавать её за неверный ключ или сетевой сбой |
| 403 | Разобрать причину запрета; не считать автоматически отсутствием модели |
| 404 | Различить неправильный маршрут и неизвестную модель по контракту и ответу |
| 429 | Ограниченный Retry-After; не переносить Gemini-классификацию суточной квоты на Polza без основания |
| 400, 413, 415, 422 | Понятная ошибка параметров, размера или формата; никаких бесконечных повторов |
| Пустой или обрезанный ответ | Сохранить запись, не вставлять сомнительный текст; применить текущую оценку тишины только с аудиодоказательствами |
| Отмена | Отменить загрузку, ожидание и отложенный повтор; сохранить/удалить CAF по действующей политике отмены |

Для `402` обновить `TranscriptionError`, `DictationFailure`, copy HUD, метаданные и обработку Retry. Основание: [Polza о типовых ошибках](https://polza.ai/collections/stt). Статус запроса и текст ответа имеют приоритет над догадками по одному HTTP-коду.

Очередь группирует блокировки по профилю: недостаточный баланс или ключ Polza не останавливает пригодные записи Gemini. Повтор запускается после явного Retry, изменения ключа/профиля, восстановления сети или старта приложения. Изменение баланса само по себе не наблюдается; периодический опрос и автоматическое переключение провайдера в этот объём не входят.

## Проверки и критерии приёмки

Автоматические проверки используют внедрённый HTTP-транспорт или `URLProtocol`, без реальных ключей и платных запросов. Проверяются multipart-байты, JSON аудиочата, правильные пути и заголовки, разбор ответов и отмена. Fixtures привязаны к каждому маршруту.

Обязательные сценарии:

1. Миграция повторяется безопасно; существующий Gemini-ключ и настройки работают как раньше.
2. Только с ключом Polza доступны все целевые модели GPT, Whisper и Voxtral; запросы не уходят в Google.
3. Выбор файловой ASR-модели отправляет multipart на `/audio/transcriptions`; выбор Small — проверенную аудиоструктуру на `/chat/completions`.
4. Изменение модели, адреса и форматировщика во время записи не меняет snapshot текущего сеанса.
5. Retry после перезапуска использует исходный профиль; удаление профиля сохраняет аудио и даёт исправимую ошибку.
6. Ошибка ключа/баланса Polza не блокирует очередь Gemini. Retry не переключает провайдера автоматически.
7. Smart/Tone выключены или честно объяснены без форматировщика; с Polza-форматировщиком его сбой не теряет исходный текст.
8. Включённый ранее Gemini Live не отправляет аудио в Google после выбора Polza.
9. Произнесённые вопросы и команды не превращаются в ответы/код; обрезанный ответ Small не вставляется.
10. Проверены граничная длительность и размер, тишина, Unicode, словарь, отсутствие сети и отмена при загрузке.
11. `swift test --package-path JotCore` и Debug-сборка приложения проходят на машине с полным Xcode; отдельно проверяется запись и вставка в TextEdit и Electron-приложение.
12. README, onboarding и Privacy описывают выбранного посредника и фактические места отправки данных. Обещания «только Google» и «без посредника» действуют только для соответствующего Gemini-профиля.
13. В чистых настройках дополнительная очистка выключена. Без второй модели и её ключа ASR работает; ни один запрос к форматировщику не отправляется. Переключатель сохраняется после перезапуска.
14. При включении очистки используется выбранная текстовая модель, при выключении — только ASR. Списки, слова-паразиты и самокоррекции проходят отдельные текстовые проверки; ошибки очистки возвращают исходный текст.
15. Пользователь может задать общий API URL и две модели или отдельный URL/ключ очистки. Запросы и секреты попадают только в выбранные профили; выключенная очистка не проверяет свой ключ сетевым запросом.
16. Язык «Автоматически», явный `ru` и другой поддерживаемый язык формируют корректные запросы. Неподдерживаемый язык объясняется, выбор сохраняется и восстанавливается в Retry. Русский интерфейс не переводит английскую диктовку.
17. Русский используется по умолчанию на обеих локалях macOS; выбор English сохраняется и применяется после перезапуска. Язык интерфейса не меняет язык диктовки. Отдельная ручная приёмка проверяет onboarding, настройки, HUD, меню, ошибки, историю, словарь, разрешения, окончания числительных и отсутствие обрезанных строк.
18. В настройках нет старых дублирующих URL/моделей/ключей и переключателей, которые не влияют на выбранный API. Все оставшиеся элементы имеют действующих потребителей.
19. Неиспользуемые заглушки и зависимости удалены; после очистки проходят сборка и тесты. Обновление существующей установки сохраняет ключи, модели, пользовательский выбор очистки, историю и словарь.

Поддержка каждой модели принимается после успешной реальной диктовки через Polza и проверки поведения на речевых примерах. Публичный каталог и список в авторизованном Playground проверены. Четыре файловые модели успешно обработали синтетический русский WAV; результаты сохранены в отдельном отчёте. Voxtral Small и отдельный API-клиент пока не проверены реальным запросом. Каталог, mock-тесты, Playground и сборка подтверждают разные части работы и не заменяют результат интеграции Jot. Полный XCTest ограничен отсутствием полного Xcode и модуля XCTest. После удаления KeyboardShortcuts ограничение PreviewsMacros устранено; автономные проверки API выполняются без XCTest.

В первый объём не входят локальный запуск моделей, новые live-протоколы, асинхронный `/media`, перевод речи, диаризация, автоматический подбор самой дешёвой модели и скрытая передача аудио резервному провайдеру. Для синхронных маршрутов из плана не нужна система удалённых job ID; она понадобится отдельно, если позже появится асинхронный API.
